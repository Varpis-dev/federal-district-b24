# Переезд с Vercel на Yandex Cloud

Приложение работает в **Yandex Serverless Containers**: серверы в России, бесплатный объём —
1 млн вызовов, 10 ГБ×ч памяти и 5 vCPU×ч в месяц. Код приложения не переписан: маршруты
по-прежнему берутся из `vercel.json`, PHP и JS-обработчики запускаются как раньше.

Что добавлено в репозиторий:

| Файл | Зачем |
|---|---|
| `yc/server.js` | Запускатель: читает `vercel.json`, запускает `api/*.js` в формате Vercel, проксирует `api/*.php` во встроенный PHP-сервер, отдаёт `public/` |
| `yc/fetch-mirror.js` | При сборке скачивает справочники с GitHub внутрь образа (для приложений, которые их используют) |
| `Dockerfile`, `.dockerignore` | Образ PHP 8.3 + Node.js |
| `.github/workflows/deploy-yandex.yml` | Автодеплой при каждом push в `main` — как было на Vercel |

Локально Docker ставить не нужно — образ собирает GitHub Actions.

---

## Шаг 1. Yandex Cloud (один раз на все три приложения)

1. Зайти в [консоль Yandex Cloud](https://console.yandex.cloud), создать платёжный аккаунт
   (нужна карта; пока укладываетесь в бесплатный объём — списаний за контейнеры нет).
2. Открыть каталог (обычно `default`) и скопировать его **ID** — это `YC_FOLDER_ID`.
3. **Cloud Registry** → «Создать реестр», тип Docker. Скопировать **ID реестра**.
   `YC_REGISTRY` = `registry.yandexcloud.net/<ID реестра>`.
   > Старый Container Registry (`cr.yandex`) закрыт для новых пользователей с 13.10.2026
   > и отключается 14.12.2026, поэтому используем Cloud Registry. Хранение образов — копейки
   > в месяц (бесплатного объёма у реестра нет).
4. **Сервисные аккаунты** → создать `github-deploy` с ролями на каталог:
   - `serverless.containers.admin`
   - `cloud-registry.artifacts.pusher`
   - `iam.serviceAccounts.user`

   Скопировать **ID сервисного аккаунта** — это `YC_SA_ID`.
5. В сервисном аккаунте: «Создать новый ключ» → **Авторизованный ключ** → скачать JSON.

## Шаг 2. GitHub (в каждом из трёх репозиториев)

Settings → Secrets and variables → Actions.

**Secrets** → New repository secret:

| Имя | Значение |
|---|---|
| `YC_SA_JSON_KEY` | содержимое JSON-ключа целиком |

**Variables** → New repository variable:

| Имя | Значение |
|---|---|
| `YC_FOLDER_ID` | ID каталога |
| `YC_REGISTRY` | `registry.yandexcloud.net/<ID реестра>` |
| `YC_SA_ID` | ID сервисного аккаунта |
| `YC_CONTAINER_NAME` | `candidate-time` / `federal-district-b24` / `bitrix-region-by-city` |

## Шаг 3. Деплой

Влить эти изменения в `main` (или Actions → «Deploy to Yandex Cloud» → Run workflow).
Через 2–3 минуты в итогах запуска появится адрес вида
`https://bba……….containers.yandexcloud.net/`. Проверка: открыть `<адрес>/__health` — должно быть `ok`.

Дальше каждый push в `main` выкатывается автоматически.

## Шаг 4. Битрикс24

В карточке приложения (там, где сейчас указан адрес `*.vercel.app`) заменить адреса на новый:

| Приложение | Адрес приложения | Адрес установки |
|---|---|---|
| Время кандидата (`candidate-time`) | `https://<новый адрес>/` | `https://<новый адрес>/install` |
| Федеральный округ (`federal-district-b24`) | `https://<новый адрес>/` | `https://<новый адрес>/install` |
| Область по городу (`bitrix-region-by-city`) | `https://<новый адрес>/` | `https://<новый адрес>/install` |

После этого открыть каждое приложение и перепривязать обработчики **на новый адрес**
(они строят ссылки по текущему домену):

- **Время кандидата** — кнопка привязки поля в настройках: тип поля обновится на `<новый адрес>/field`.
- **Федеральный округ** — кнопка привязки: старые подписки на события (в том числе на Vercel)
  удаляются, создаются новые на `<новый адрес>/events`.
- **Область по городу** — «Переподключить автозаполнение»: старая подписка `ONCRMDEALADD`
  на Vercel теперь тоже удаляется (доработано при переезде).

## Если что-то не так

- **Логи**: консоль → Serverless Containers → контейнер → «Логи».
- **Нужен свой домен** (например `apps.vitako.ru`): подключить через API Gateway или
  Certificate Manager, затем задать переменную `PUBLIC_HOST` = этот домен и перезапустить workflow.
  Приложения строят ссылки по `PUBLIC_HOST`.
- **Первое открытие после простоя дольше обычного** — это холодный старт контейнера (1–3 с), дальше быстро.
- В `federal-district-b24/api/field-v2.php` SDK Битрикса грузится с `unpkg.com`. Если у кого-то поле
  не прорисуется, этот файл стоит положить в `public/` и подключать локально.
